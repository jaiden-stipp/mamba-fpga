# Research review and next experiments — 2026-10-22

## Recommendation

The strongest continuation is **a transaction-aware reader plus a bounded precision working set**, evaluated by correct long-context responses delivered within fixed deadlines. Keep [P003 recurrent rounding](../experiments/planned/P003-recurrent-rounding.md) as an alternative Mamba/RTL thesis. Establish the optimized serving baseline before committing to a new architecture.

This is a research recommendation, not a finding that the proposed mechanism is novel. Low-bit KV storage, fused attention, query-adaptive precision, FPGA mapping, cache reuse and GPU–FPGA splitting all have substantial prior art. The opportunity is a precise combination of representation, reader and policy whose gains survive quality, memory capacity and full-system costs. It is possible that the strongest baselines leave too little headroom. The proposed gates make that outcome inexpensive to discover.

The six [new experiment protocols](../experiments/planned/README.md) specify hypotheses, baselines, controls, hardware stages, stopping criteria and a presentable output. [E005](../experiments/005-read-granularity/README.md) already executes the initial layout screen. [E004](../experiments/004-kv-serving/README.md) contains the actual optimized-engine serving pilot and its separate report.

## Work completed in this update

Screened 38 accessible primary sources, with relevant full-text sections inspected for the closest systems and explicit abstract-only labels elsewhere. Wrote six ranked research protocols plus a baseline-confirmation protocol. Ran 147 analytical layout configurations and an actual GPU serving pilot: eight selected configurations and 188 scored responses, including 124 resident-prefix questions. Preserved failed setup checks and the raw evidence from an operational recovery. No FPGA synthesis or new board run was performed in this update.

Measured KV allocations for eight 17,408-token slots were 10.160 GiB (Q8) and 5.379 GiB (Q4). The eight-slot F16 configuration was analytically guarded out; it was not observed to OOM. The largest selected resident active-wave rate was 3.136 correct on-time responses/s for Q8/eight slots. This excludes loading and orchestration gaps, uses a different population from four-slot controls, and is not evidence of quality-matched superiority. See [the complete serving report](../experiments/004-kv-serving/serving_report.md).

The layout model produced another useful screen: at a stipulated 64-byte fetch unit, uniform four-bit prefixes cost 34,304 modeled bytes with group-major storage and 17,920 with tiled/global planes, including metadata. A random mix of two-/six-bit groups has the same four-bit mean, but a global-plane layout costs 26,112 modeled bytes. Equal mean precision therefore need not imply equal fetched bytes. These are analytical counts, not measured hardware traffic, quality or acceleration.

Seven generated artifacts reproduced byte-identically from the preserved evidence. The serving analysis passed 212 assertions and the analytical sweep passed 170. The local streaming test also covered a large terminal event after correcting a client parsing artifact. See [validation details](../docs/research-validation-2026-10-22.json). These checks establish reproducibility and consistency; they do not substitute for replication or statistical confirmation.

## What the literature changes

### Storage and execution are separate research problems

A compressed code can occupy fewer bytes while its reader performs more work. Reading one nibble from each byte still fetches the byte; fetching an aligned bus unit may also bring unused neighboring bits. Scale factors, selection maps, decoded intermediates and insertion writes add traffic. This distinction is already explicit in [ReadKV](https://arxiv.org/abs/2610.11245), which includes a single-layer timing and physical-traffic study. Its tested dense kernel is still faster than its compressed reader. A reported improvement against one quantized codec therefore cannot be interpreted as a complete-serving speedup over dense execution.

[SAW-INT4](https://arxiv.org/abs/2604.19157) makes serving layout and fused execution central to the design. [UltraQuant](https://arxiv.org/abs/2606.20474v3) goes further into hardware-native low-precision execution and agent-trace serving; its benefits relative to FP8 depend on memory pressure. These are strong baselines, not merely related papers to cite. A reference implementation that reconstructs full FP16 KV before ordinary attention is useful for checking quality but inadequate as the only performance baseline.

**Our implication:** P001 must compare actual transactions at a matched quality level, then carry the winning design into serving. E005 is only an optimistic address model: it cannot predict latency, attention accuracy or native FPGA bandwidth.

### Reuse has several different meanings

Prefix reuse avoids rebuilding the same context. Cold-page compression changes representation while state is offloaded. Cross-context repair corrects state when its conditioning prefix changes. A precision working set retains already available refinement information for subsequent reads. These mechanisms have different correctness and cost conditions.

Recent work makes broad reuse claims especially crowded: [KV²](https://arxiv.org/abs/2610.03198v2) selectively reconstructs tokens to improve reusable-cache eviction scores; [Budgeted Cache Repair](https://arxiv.org/abs/2610.02233v2) recomputes selected rows after cross-context reuse; [ReCache](https://arxiv.org/abs/2608.19662) changes resource attention/positions for reusable tool schemas; [CacheSlide](https://www.usenix.org/conference/fast26/presentation/liu-yang) addresses positional drift. These are not interchangeable implementations of the proposed precision working set.

**Our implication:** P002 starts with identical prefixes/positions and an offline oracle. It must beat ordinary decoded-page LRU after charging retained backing bits and working-set memory. If the oracle has little benefit, do not build a controller just to generate an experiment.

### Model behavior can consume a hardware gain

NVIDIA's [Nemotron 3 Super report, §4.3](https://research.nvidia.com/labs/nemotron/files/NVIDIA-Nemotron-3-Super-Technical-Report.pdf) reports that recurrent-state precision can change completion length, and studies stochastic rounding as a remedy. That makes natural answer length a meaningful hardware metric. A lower per-token cost can be offset by generating more tokens or repeating text.

[KVarN](https://arxiv.org/abs/2606.03458) and [PM-KVQ](https://proceedings.iclr.cc/paper_files/paper/2026/hash/afb8caec018d3c8f6ef8b81fa52386fe-Abstract-Conference.html) also make long autoregressive generation relevant to quantization. [KVFundaBench/ShotKV](https://proceedings.mlr.press/v306/liu26dz.html) explicitly examines reasoning beyond sparse retrieval. A short needle lookup cannot certify that a cache scheme preserves complex reasoning.

**Our implication:** use both a fixed-token timing control and natural-EOS task evaluation. The primary claim should be cost per correct, timely answer. For Mamba, place quantization inside the recurrence; comparing a compressed frozen state once misses error feedback.

### FPGA resources matter at the level of the whole bottleneck

[LUT-LLM](https://arxiv.org/abs/2511.06174v2) already explores replacing arithmetic with trained lookup computation, including centroid search and memory-port constraints. [LowRank-SSM v2](https://arxiv.org/abs/2608.02954v2) targets projection traffic with a compatible factorized datapath. [FAST-Prefill](https://arxiv.org/abs/2602.20515) targets sparse-prefill index generation and memory reuse. These are substantive accelerator designs; a smaller phase rotator does not by itself compete with them.

**Our implication:** profile the fraction of complete execution affected by the proposed component. If a component is 10% of runtime, even making it infinitely fast caps overall speedup at about 1.11×. This is Amdahl's bound, not a pessimistic hardware assumption. Research that changes which bottleneck dominates can still be valuable, but demonstrate that transition.

## Experiments that can support a substantive claim

### Recommended sequence

1. **Baseline and task calibration:** follow [P000](../experiments/planned/P000-serving-confirmation.md), repeat E004, diagnose per-task failures and improve the quality set. An answer the F16 model cannot produce is evidence about the task/model pair, not automatically about compression. Keep the original protocol/results and mark all later changes.
2. **P001 reader headroom:** replay genuine quantizer-selected schedules through E005's address counter; add a faithful codec and attention computation. A uniform-depth toy win is insufficient.
3. **P002 reuse oracle:** test whether repeatedly useful refinements exist and repay their memory footprint. This can kill the idea before RTL implementation.
4. **One mechanism:** implement either transaction-aware precision allocation or a bounded refinement policy first. Ablate it separately; combining both immediately makes causality hard to defend.
5. **RTL and serving:** validate the bounded reader on DE2-115 and request an HBM platform for the larger memory-system claim if the measurements justify it. Close the loop with identical-arrival serving at matched quality.

P003 is a coherent alternative with a different scientific target: preserving behavior through recurrent precision feedback. P004/P005/P006 should be selected only if profiling and prior-art reproduction indicate better opportunity. They are not extra features that all belong in the first paper.

### Shared controls and statistics

**Quality:** freeze task sets, scoring and acceptable loss before confirmation. Use independent documents/sessions; many questions on one document are correlated. Report unconditional accuracy, strict format, truncation and latency failures. Also report paired differences on the same questions. A secondary diagnostic restricted to F16-correct questions can isolate damage but must not replace the unconditional primary score.

**Noninferiority:** eight documents cannot establish a one-percentage-point quality margin. If independent cases had zero new failures, the rough rule-of-three bound would put the one-sided 95% failure-rate bound near 3/n, requiring about 300 independent opportunities merely to bound an added failure probability around 1%. This is not a full paired noninferiority sample-size calculation: baseline errors, discordant outcomes, task strata and clustering require a dedicated power analysis. A claim across several tasks needs each task's uncertainty, not just an aggregate average.

**Timing:** use at least three independent trials for confirmation, rotate/randomize configuration order, warm up relevant shapes, monitor clock/temperature/competing allocations and include failed runs. Timing repeats are not independent quality samples. Compare equal arrival traces and fixed input/output policies. Closed-loop populations are useful load curves but do not establish identical-load superiority. Report queueing, cold prefill, resident decoding and rebuilding separately.

**Memory:** count weights, retained state, scales, codebooks, working sets, scratch, draft/rollback buffers and allocator overhead that are simultaneously live. Do not add unrelated peaks or count a codebook as free because it is shared across requests. Compare both equal memory and equal quality; a method may win only when capacity limits the baseline.

**Hardware:** preserve requested and actual placement/format logs. Runtime profiling is required for physical DRAM-byte and dispatch claims. Distinguish measured board clock from fitted Fmax and tool-estimated power from energy measurements. Compare equal resources or explain the resource/throughput frontier. Host staging, PCIe synchronization and all conversions belong in the hybrid boundary.

**Success:** the prospective target is at least 20% higher correct deadline-qualified throughput over the strongest compatible compressed baseline, with a predeclared per-task quality margin. This is a decision threshold to justify more work, not a universal publication rule. A smaller effect may matter in production, but must be robust and causally explained. A faster component with no complete-system effect does not meet the stated project objective.

## How to explain the project in a presentation

“The model keeps a memory of the conversation. Compressing it lets us store more conversations, but the model still has to read that memory for every new word. Our question is whether we can organize and reuse the useful parts so it reads less without giving worse answers or missing response deadlines.”

Distinguish three quantities on the slide: **stored bytes**, **bytes fetched**, and **correct answers on time**. Show a worked example where two layouts retain the same bits yet fetch different bus units. Then show the quality/capacity/latency frontier from real serving. Explain that an FPGA can give precise control of the reader and memory pipeline; this is a hypothesis to verify, not an automatic advantage over a GPU.

For P003: “A recurrent model repeatedly updates the same state. A small rounding error becomes part of the next update. We test whether a cheaper state representation changes its answers or makes it talk longer, then design rounding hardware that saves total answer cost.”

The final demo should be understandable without quantization jargon: several users ask difficult questions about long documents, and the counter records only correct answers delivered before the deadline. A side panel explains the actual memory and energy costs. If the new method does not improve that counter, say so; that result redirects the design.

## Search scope and limits

Reviewed on 2026-10-22 using arXiv primary pages/full-text sections, original conference proceedings, author code/documentation and original technical reports. Search families included: low-bit KV serving and fused execution; progressive/query-adaptive precision; FPGA KV burst/coalescing and memory ports; repeated-query precision/cache reuse; recurrent state quantization and stochastic rounding; GPU–FPGA splitting; lookup/rank-reduced projections; long-context and reasoning evaluation. Follow-up searches deliberately sought work that would invalidate the proposed claims, including self-refining caches, budgeted cache repair and compression-aware speculation.

Thirty-eight accessible primary records are annotated above; an additional HALO publisher record was access-limited. Abstract screening and full-text inspection are labeled separately. The machine-readable [source register](sources-2026-10-22.json) records the exact URLs and inspection scope. These searches identify strong overlaps and plausible gaps; they cannot certify that an idea has never been published. Before asserting novelty, reproduce the closest methods, inspect their code and references, follow forward citations, and have the supervisor review the narrowed mechanism and comparison.
