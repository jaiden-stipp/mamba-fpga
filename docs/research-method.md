# Research method

1. Define a useful system-level objective and falsifiable mechanism.
2. Review primary sources and strong existing baselines.
3. Profile and bound possible total benefit before optimizing a block.
4. Freeze data splits, quality metrics, budgets, timing boundaries and decision rules.
5. Verify numerical/semantic behavior before performance measurement.
6. Count metadata, padding, indices, working sets, scratch, shared parameters, conversions, transfers and fallbacks.
7. Preserve raw observations, failures, revisions, seeds and asset hashes.
8. Separate exploratory changes and held-out confirmation.
9. Continue/revise/retire from evidence and retain negative results.

For FPGA work distinguish simulation, synthesis, fitted timing and board operation. For serving distinguish cold loading, resident execution, queueing, capacity, raw throughput and correct deadline-qualified throughput.
